# 訪問介護FC 管理システム（モック）

要件: [../docs/requirements.md](../docs/requirements.md)

## 起動

```bash
cd app
npm install
npm run dev
```

http://localhost:5173 を開きます。初回はダミーデータが自動投入されます。

## 画面の切り替え

画面右上の「ログイン中」で利用者を切り替えます（認証はモックのため省略）。

| 区分 | 主なユーザー | 画面 |
|---|---|---|
| ① 本部 | 山田（本部長・決裁）/ 佐藤・鈴木（開発）/ 高橋（SV）/ 田中（経理） | `/hq` |
| ② 加盟希望者・オーナー | 案件ごとの加盟者（P0〜P6・運営中） | `/fc` |
| ③ 店舗スタッフ | 世田谷・川崎高津・船橋の管理者／サ責／ヘルパー | `/field` |

同じブラウザの別タブで本部と加盟者を並べると、操作がリアルタイムに反映されます（ログインユーザーはタブごとに別）。

## デモシナリオ（ダミーデータの状態）

| 案件 | 状態 | 試せる操作 |
|---|---|---|
| 渡辺（ミサキケア） | P1・NDA署名待ち | 加盟者で署名 → 本部長で署名 → 締結・タスク自動完了 |
| 小林（コバヤシ） | P2・申込書提出済 | 本部で書類確認／差し戻し、本部長で加盟可否を決裁 |

| 吉田（よしだ福祉） | P4・入金報告あり | 経理で消込 → 領収書発行で P5 へ |
| 山本（やまもとケア） | P5・人員の書類が差し戻し | 加盟者で再提出 |

「設定・データ」画面からいつでもダミーデータを初期化できます。

## データベース（Firebase）

- 既定: ブラウザ内（localStorage）で動作
- Firestore を使う場合: `.env.example` を `.env.local` にコピーして Firebase プロジェクトの設定を記入し、再起動 → 「設定・データ」から「ダミーデータを投入し直す」
  - `firestore.rules` はモック用（全許可）です。本番では使わないでください
- Firestore エミュレータ: `VITE_USE_FIREBASE_EMULATOR=true` にして `firebase emulators:start`（Java 11 以上が必要）

コレクション構成は requirements.md §9.1.1 を参照。

## 公開（Firebase Hosting）

- URL: https://houmonkaigo-fc.web.app （プロジェクト `houmonkaigo-fc`、Firestore は asia-northeast1 想定）
- 再デプロイ: `npm run build && firebase deploy --only hosting`
- ルール反映: `firebase deploy --only firestore:rules`（モック用。2027/2/28 まで誰でも読み書き可）
- Firestore が空の状態で最初にアクセスすると、ダミーデータが自動投入されます

## モックで省略しているもの

- 認証（メールの認証コードは送信せず、画面右下に表示）
- ファイルのアップロード（ファイル名のみ記録）
- タイムスタンプ、法的要件の詰め、銀行明細の自動取込
- freee CSV の列は「取引のインポート」形式を想定。本番前に freee の最新仕様と照合が必要
- 売上は訪問1回あたりの概算単価で計算（介護報酬の単位計算は未実装）

## 主なファイル

- `src/lib/workflow.ts` — 加盟ワークフローのテンプレート（フェーズ・タスク・依存関係・期限）
- `src/lib/actions.ts` — 業務操作（タスク完了・差し戻し・電子契約・請求・消込・開業処理・月次）
- `src/lib/db.ts` — データ層（Firestore / localStorage 切替）
- `src/lib/seed.ts` — ダミーデータ生成
- `src/components/ContractView.tsx` — 内製電子契約（承認・メール認証・署名・ハッシュ）
