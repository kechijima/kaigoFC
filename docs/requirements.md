# 介護FC 加盟店管理システム 要件整理（ドラフト v0.1）

作成日: 2026-11-19
ステータス: たたき台（未確定事項は §10 に集約）

> 前提: **訪問介護事業のフランチャイズ**（確定）。開業準備フェーズ（§4 P5）と業務システム（§5.3）は訪問介護の人員・設備・運営基準、指定申請に合わせています。

---

## 1. 目的とスコープ

### 1.1 目的
- 加盟希望者の問い合わせから契約・入金・開業準備・開業までの一連のタスクを、**ワークフロー形式で漏れなく進行管理**できるようにする。
- 本部・加盟店の双方が「今どこまで進んでいて、次に誰が何をするか」を同じ画面で把握できるようにする。
- 開業後の加盟店運営（ロイヤリティ請求、報告、お知らせ、マニュアル配布）も同じ基盤で扱う。

### 1.2 今回（モック段階）のスコープ
| 対象 | モックで作る | 後回し |
|---|---|---|
| 本部管理画面 | ○ | |
| 加盟店管理画面 | ○ | |
| 加盟店が利用する業務システム | 画面イメージのみ（主要2〜3画面） | 本格機能 |
| 加盟ワークフロー | ○（一通り操作できる） | ワークフローの自由編集UI |
| 認証・権限 | ロール切替ボタンで代用 | 本番認証、SSO |
| 電子契約 | **内製**（§5.4）。作成→承認→署名→締結の動きを再現 | 本人確認の実送信、タイムスタンプ、法的要件の詰め |
| 請求・入金 | **内製**（§5.5）。請求発行→入金報告→消込の動きを再現 | 銀行明細の自動取込、会計連携 |
| データ | ダミーデータ（ブラウザ内保存） | DB、バックアップ |

## 3. システム構成（3つの画面群の役割分担）

```
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│ ① 本部管理画面     │◀───▶│ ② 加盟店管理画面   │◀───▶│ ③ 加盟店業務システム │
│ 全加盟店を横断管理  │      │ 自店舗の本部対応    │      │ 現場の日々の業務    │
└──────────────────┘      └──────────────────┘      └──────────────────┘
        共通: 加盟店マスタ / ワークフロー / 書類 / 請求 / お知らせ
```

- **① 本部管理画面**: 全加盟店・全案件のパイプライン、タスク割当、承認、請求、全体KPI。
- **② 加盟店管理画面**: 加盟希望者〜オーナーが使う「本部とのやりとり」画面。自分のタスク、提出書類、契約、請求、お知らせ、マニュアル。
- **③ 加盟店業務システム**: 開業後の現場業務。介護なら利用者管理・スケジュール・記録・実績報告など。本部へ売上・実績を連携しロイヤリティ計算の元データにする。

> 論点: ②と③を1つのアプリ内のメニュー違いにするか、別アプリにするか（§10 Q3）。

## 4. 加盟ワークフロー（中核要件）

### 4.1 フェーズ全体像

```
問い合わせ → 説明会/面談 → 加盟申込・審査 → 契約 → 入金 → 開業準備 → 開業 → 運営
   P0            P1              P2          P3     P4       P5        P6     P7
```

各フェーズは「タスクの集合」で、**全必須タスク完了＋（必要なら）本部承認**で次フェーズへ進む。

### 4.2 フェーズ別タスク一覧（たたき台）

凡例 — 担当: 本=本部 / 加=加盟希望者・加盟店　種別: 作業 / 提出 / 承認 / 入金 / 確認

#### P0 問い合わせ
| # | タスク | 担当 | 種別 | 完了条件 |
|---|---|---|---|---|
| 0-1 | 問い合わせ受付・リード登録 | 本 | 作業 | 基本情報登録 |
| 0-2 | 初回連絡・資料送付 | 本 | 作業 | 送付日記録 |

| 1-2 | 説明会参加 | 加 | 確認 | 参加記録 |
| 1-3 | 秘密保持契約（NDA）締結 | 加 | 提出 | 署名済NDA |
| 1-4 | 事業計画・収支シミュレーション提示 | 本 | 作業 | 資料添付 |

| # | タスク | 担当 | 種別 | 完了条件 |

#### P4 入金
| # | タスク | 担当 | 種別 | 完了条件 |
|---|---|---|---|---|
| 4-1 | 加盟金・保証金・研修費の請求書発行 | 本(経理) | 作業 | 請求書発行 |
| 4-2 | 入金 | 加 | 入金 | 振込実施の報告 |

> 分割払い・期限超過時の督促フローも対象（期限超過でアラート）。

|---|---|---|---|---|
| 6-1 | 開業日確定・告知 | 本+加 | 作業 | 開業日登録 |

#### P7 運営（ワークフロー外の継続業務）
- 月次: 売上/実績報告 → ロイヤリティ計算 → 請求 → 入金確認
- SV巡回・定期面談、各種研修、契約更新（期限の○ヶ月前にワークフロー自動起票）
- 解約・譲渡時は別ワークフロー（将来）

### 4.3 ワークフロー機能要件
| ID | 要件 | モック |
|---|---|---|
| WF-01 | フェーズ・タスクを**テンプレート**として定義し、加盟案件ごとに展開（インスタンス化）できる | ○（固定テンプレ） |
| WF-02 | タスクごとに担当（本部担当者／加盟店側）、期限、必須/任意、種別を持つ | ○ |
| WF-03 | タスク間の**依存関係**（例: 審査承認前に契約タスクは着手不可） | ○ |
| WF-04 | 「承認」種別タスクは指定承認者のみ完了可。差し戻し（コメント付き）ができる | ○ |
| WF-05 | 「提出」種別タスクはファイル添付→本部確認で完了 | ○（添付はダミー） |

| WF-07 | フェーズ内の必須タスクが全完了で次フェーズへ自動遷移（または承認後に遷移） | ○ |
| WF-08 | 期限超過・期限接近のアラート表示、担当者への通知 | ○（画面表示のみ） |
| WF-09 | タスクごとのコメント・やりとり履歴、操作ログ | ○ |
| WF-10 | 案件の中断・辞退・失注の記録（理由付き） | ○ |
| WF-11 | テンプレートを本部がGUIで編集 | 後回し |
| WF-12 | 条件分岐（例: 法人設立済みなら5-1スキップ） | △（スキップ操作で代用） |

### 5.4 共通機能: 内製の電子契約・書類締結
外部の電子契約サービスは使わず、**システム内で締結まで完結**させる。NDA・加盟契約書・開示書面の受領確認・覚書・更新契約など、ワークフロー内の「署名が必要な書類」すべてで共通に使う。

| ID | 要件 | モック |
|---|---|---|
| EC-01 | 契約書テンプレート管理（差し込み項目: 加盟者名、店舗名、テリトリー、加盟金、ロイヤリティ率、契約期間 等） | ○（固定テンプレ1〜2種） |
| EC-02 | 案件データから契約書ドラフトを自動生成し、本部で編集できる | ○ |
| EC-03 | 社内の事前承認（法務・決裁者）を経てから相手方へ送付 | ○ |
| EC-04 | 署名順序の設定（例: 加盟者 → 本部代表者） | ○（固定順） |
| EC-05 | 署名者の本人確認: メール/SMSのワンタイムコードによる認証 | △（コード入力の画面のみ、送信はダミー） |
| EC-06 | 署名操作: 内容の全文表示 → 同意チェック → 署名（氏名入力 or 手書きサイン） | ○ |
| EC-07 | 締結後のPDF確定（以後は編集不可）、ハッシュ値の記録による改ざん検知 | △（「確定」状態とハッシュ表示のみ） |
| EC-08 | 合意締結証明（誰が・いつ・どのIP/端末から・どの版に署名したか）の記録と出力 | ○（ログ表示） |
| EC-09 | 差し戻し・修正依頼・取消（理由付き）、版管理 | ○ |
| EC-10 | 署名期限とリマインド | ○（画面上のアラート） |
| EC-11 | 契約書の検索・保管（契約日・金額・相手方で検索できるようにする） | ○ |
| EC-12 | タイムスタンプ付与（認定タイムスタンプ局との連携） | 本番で検討 |

**状態遷移（契約書）**
```
下書き → 社内承認待ち → 送付済（署名待ち） → 加盟者署名済 → 本部署名済 = 締結完了
             ↓差戻し            ↓修正依頼/取消
           下書き              下書き / 取消
```

### 5.5 共通機能: 請求・入金（内製）
- 請求書は本システムで発行（PDF）し、入金消込も本システムで行う。会計ソフトにはCSVで出力する想定。
- モックでは「入金報告」ボタン→経理が「消込」ボタンを押すと、入金タスクが完了する動きとする。
- 本番での入金データの自動取込（銀行明細CSV・振込通知API）は後で決める。

## 6. 主要データ（エンティティ）

| エンティティ | 主な項目 |
|---|---|
| 加盟案件（Deal） | 案件ID、希望者、候補エリア、現在フェーズ、ステータス（進行中/保留/辞退/成約）、担当者 |
| 加盟希望者/オーナー（Party） | 氏名/法人名、連絡先、法人番号、反社チェック結果 |
| 店舗（Store） | 店舗名、所在地、事業種別、指定事業所番号、開業日、ステータス |
| 契約（Contract） | 契約種別、締結日、期間、自動更新、テリトリー、加盟金、ロイヤリティ条件 |
| ワークフローテンプレート | フェーズ、タスク定義、依存関係、既定担当、既定期限（相対日数） |
| タスク（Task） | 所属案件、フェーズ、種別、担当、期限、状態（未着手/対応中/確認待ち/差戻し/完了/スキップ） |
| 書類（Document） | 種類、ファイル、提出者、確認状態、版 |
| 請求（Invoice）/入金（Payment） | 費目、金額、期限、入金日、消込状態 |
| お知らせ（Notice） | 配信対象、本文、既読 |
| 操作ログ（AuditLog） | 誰が・いつ・何を |

---

## 7. 権限の考え方
- 本部ユーザー: 全案件閲覧可。編集・承認はロール別。
- 加盟店ユーザー: **自分の案件・店舗のみ**閲覧可。本部内部メモ（審査メモ等）は非表示。
- 承認タスクは承認者ロールを持つユーザーのみ完了可。

## 8. 非機能要件（本番時の論点・モックでは対象外）
- セキュリティ: 個人情報・要配慮個人情報（介護記録）を扱うため、アクセス制御・暗号化・ログ保全
- 3省2ガイドライン等、医療介護情報の取扱いガイドラインへの準拠検討
- 電子契約の内製に伴う法的有効性の確保: 電子署名法上の位置づけ（事業者署名型/立会人型の方式選定）、本人確認の強度、認定タイムスタンプ、改ざん検知、締結記録の長期保存。本番前に弁護士確認が必要
- 電子帳簿保存法（電子取引データの保存要件: 真実性・可視性）、インボイス制度に対応した請求書
- 可用性・バックアップ、監査ログ保持期間
- スマホ対応（特に③の記録入力）

## 9. モックの進め方（提案）

### 9.1 技術構成（確定）
- フロント: React + TypeScript + Vite + Tailwind CSS
- DB: **Firebase（Cloud Firestore）**。本番では Firebase Authentication（メールリンク/ワンタイムコード）と Cloud Storage（書類ファイル）も使う
- モック段階では、Firebaseの設定（`.env`）が無くてもブラウザ内のローカルDBで同じように動く。設定すればFirestoreに切り替わる
- ダミーデータは画面の「ダミーデータ投入」から、ローカル／Firestoreのどちらにも投入できる
- 画面右上で「本部 / 加盟店 / 現場スタッフ」を切り替えてデモする
- 署名時のメール認証は、モックではコードを画面に表示して代用する
- freee向けの仕訳CSVを請求・入金画面から出力する

### 9.1.1 Firestore コレクション
| コレクション | 内容 |
|---|---|
| `users` | 本部・加盟店のユーザー（ロール、所属） |
| `deals` | 加盟案件（希望者情報、現在フェーズ、ステータス、開業希望日） |
| `tasks` | ワークフロータスク（`dealId`、フェーズ、種別、担当、期限、状態、コメント） |
| `contracts` | 契約書（本文、状態、署名記録、ハッシュ） |
| `invoices` | 請求（費目、金額、期限、入金報告、消込） |
| `stores` | 店舗（開業後。指定事業所番号、開業日） |
| `notices` | お知らせ |
| `clients` | 訪問介護の利用者（店舗別） |
| `helpers` | ヘルパー（店舗別） |
| `visits` | 訪問予定と訪問記録 |
| `monthlyReports` | 月次実績報告（ロイヤリティ算定用） |
| `auditLogs` | 操作ログ |

### 9.2 モックで通したいデモシナリオ
1. 本部が新規リードを登録 → 説明会実施
2. 加盟希望者が申込書・審査書類を提出 → 本部が審査・承認
3. 本部が開示書面交付・契約書作成 → 双方が締結
4. 加盟金請求 → 加盟店が入金報告 → 経理が消込
5. 開業準備タスク（物件承認、指定申請、研修…）を進める → 最終チェック承認
6. 開業 → 店舗が「運営中」になり、業務システムが使えるようになる
7. 月次実績報告 → ロイヤリティ請求

### 9.3 マイルストーン案
| ステップ | 内容 |
|---|---|
| M1 | 要件確定（本書の未確定事項を解消） |
| M2 | 画面一覧・画面遷移図 |
| M3 | 本部管理画面＋ワークフローのモック |
| M4 | 加盟店管理画面のモック（M3と連動） |
| M5 | 業務システムの画面イメージ＋月次報告の連携デモ |
